- 预留接口 /api/auth/bridge：V1.0 实现与资料百事通用户库token互认

- 愿望处理：查看联系方式、修改状态、删除
- 操作日志：注册/登录/许愿/修改/删除 全程留痕（最近100条）

【积木底座】（2026-10-14）

【用户】
帮我把本次全部内容和信息生成一个文件，后续生成其他程序时
或者编译网页时，可以调用和增加、修改、查找。这个网站作为
一个积木的底座，后续的工具都慢慢进行加入。

【AI开发团队】
已将生态改造为「积木底座」架构：新增 ecosystem.json 作为
生态单一数据源，网站改为从该文件读取数据。后续新增工具
只需往底座里加一块积木，全站自动生效，无需改动代码。

一、底座文件 ecosystem.json（人可读 + 程序可读）
十个章节：
- meta           生态元信息（名称/域名/版本/作者/微信/定位/安全说明）
- products       产品矩阵（13位积木：编号/中英文名/人群/状态/说明/路径/端口）
- hardware       硬件探讨区（6项）
- subdomains     子域名规划（8条，含状态与备注）
- infrastructure 基础设施（域名/服务器/隧道/部署计划）
- apis           接口目录（19条，含方法与权限）
- stages         版本阶段（V0.1已完成 → V2.0规划）
- conventions    工程约定（8条）
- history        生态大事记（6条）
- todos          待办清单（6条）

安全约束：底座文件为公开数据源，禁止写入任何密码、密钥、
Token；服务器与第三方凭据一律放在腾讯云站内信 / Windows
凭据管理器，不落库不落文件（已加入自动化测试校验）。

二、网站改为读取底座（不再硬编码数据）
- app.py 移除 PRODUCTS / HARDWARE 常量，改为 load_ecosystem()
  按文件修改时间自动热加载：改 ecosystem.json 即生效
- 首页主打区、产品矩阵、硬件探讨区、开放生态区全部由底座驱动
- 矩阵卡片数量随底座自动变化；编号自动重排为 01..N，
  「待添加」恒在末位

三、底座调用接口（供其他程序 / 网页 / 子站使用）
- GET    /api/ecosystem/manifest        底座全量数据（读取入口）  公开
- GET    /api/ecosystem/status          生态总览                  公开
- GET    /api/ecosystem/search?q=关键词 全底座查找（产品/硬件/子域名/接口） 公开
- GET    /api/products                  产品矩阵                  公开
- GET    /api/brands                    生态品牌                  公开
- POST   /api/ecosystem/products        新增积木（自动编号）      管理员
- PUT    /api/ecosystem/products/<编号> 修改积木                  管理员
- DELETE /api/ecosystem/products/<编号> 移除积木（编号自动重排）    管理员

四、新增一块积木的两种用法
方式A（推荐·改文件）：在 ecosystem.json 的 products 数组加一条
  {"no":"", "name":"新工具名", "en":"", "scope":"适用人群",
   "icon":"🧩", "status":"规划中", "main":false, "url":"", "desc":"说明"}
  保存后刷新网页即可看到（编号可留空，系统会统一重排）
方式B（调接口·管理员）：POST /api/ecosystem/products
  {"name":"新工具名","scope":"适用人群","desc":"说明","status":"规划中"}
  系统自动编号并插在「待添加」之前

五、其他程序如何「调用」本生态
1. 读取 http://<门户地址>/api/ecosystem/manifest 获取全部生态信息
2. 局部查询用 /api/ecosystem/search?q=关键词
3. 新工具上线后，把它的 url 填进 products 对应条目，门户矩阵
   卡片即可直接点击跳转；同时可在 subdomains 中规划子域名

【需求确认（四项决策）】
1. 使用模式：多用户各自独立（与现有登录体系打通，每人独立身份证/历程链，互不可见）
2. 交付形态：三端响应式网页（电脑/手机/平板自适应，2027 星霓暖赛博风）

【设计思路（去中心化思维，非公链）】
- DID：did:mars:ecojia:<32位hex>，首次进入自动铸造，终身不变
- 内容指纹：payload_hash = SHA-256(规范化JSON，键排序+紧凑格式)
- 区块哈希：block_hash = SHA-256(block_no|prev_hash|action|record_id|payload_hash|created_at)
- 区块动作：genesis 创世 / create 新增 / update 修改 / delete 删除 / identity 身份
- 软删除：删除只留痕不物理清除，旧版本区块永久保留
- 一键验真：逐块重算 + 当前记录内容与链上指纹比对，能定位到具体哪条被改
- 数据自持：一键导出「火星护照」JSON（schema ecojia.marsid.passport/1.0），可迁移、可离线保存
- 公开页：/hx/card/<did>，只展示公开见证记录；私密记录永不外泄；等级按全量计算
